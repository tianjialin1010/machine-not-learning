总评：硬件是真好，网络是真坑。

这台机器算力和内存几乎无短板——GB10 把 27B 量化模型 100% 塞进 GPU（34 GB 统一内存占用），跑出 13.0 tokens/s，反推有效显存带宽约 221 GB/s，达到 273 GB/s 理论峰值的 81%，属于该架构的满血表现。磁盘 4.6/5.8 GB/s 也是第一梯队。
唯一的硬伤是国际出网被墙得很彻底：pypi.org、download.pytorch.org、nvcr.io（NVIDIA NGC）、registry-1.docker.io（Docker Hub）四个全部不可达。这意味着手册里推荐的「用 NGC 容器省环境折腾」这条路在这台机器上根本走不通，必须改用国内镜像源。这个坑不提前踩，第一天就得卡住。

2性能实测数据

2.1 AI 推理 —— 最关键的一项

节点上已预装 ollama 0.33.2 和模型 Qwen3.8-27B-GGUF（17 GB 权重），直接实测：

指标实测评价
模型加载后处理器100% GPUGPU 全卸载
显存 / 统一内存占用34 GB（权重 + 262144 上下文 KV）充沛
生成速度13.0 tokens/s（256 token / 19.72 s）满血
预填速度（prompt eval）99.4 tokens/s（35 token / 0.35 s）正常
推理时 GPU 利用率96%打满
推理时温度 / 功耗47 °C / 44 W凉快、余量巨大
端到端总耗时20.16 s—
13 tokens/s 是好还是差？算一下就知道了。
17 GB 的模型每生成 1 个 token 都要把全部权重过一遍，所以理论上限 = 内存带宽 ÷ 模型体积 = 273 GB/s ÷ 17 GB ≈ 16.1 tokens/s。
实测 13.0 tokens/s → 有效带宽 13.0 × 17 GB ≈ 221 GB/s，达成率 81%。
结论：这不是「慢」，是接近这块芯片的物理天花板。想更快只有一个办法——换更小的模型（用 7B/8B 轻松上 40+ tokens/s）。

别被这个数字误导。CPU 侧的单流 numpy 测试远达不到 273 GB/s 标称值——因为 GB10 的 20 个 Arm 核内存级并行度有限，而 273 GB/s 是 GPU 与 CPU 共享总线的能力上限，主要靠 GPU 侧驱动。
真正的带宽证据在 2.1 节：推理反推出 GPU 侧有效带宽 221 GB/s。所以「统一内存带宽到底是满血还是残血」这个问题，答案是满血（81% 达成率），CPU 侧那 46 GB/s 属于架构特性，不是你分到了差机器。

5上手建议（照着做能省一天）

5.1 pip 必须换源，否则装什么都是超时

# 永久配置国内源
pip3 config set global.index-url https://mirrors.aliyun.com/pypi/simple/
pip3 config set global.trusted-host mirrors.aliyun.com

# Ubuntu 24.04 的 Python 受管控，装包需要加参数
pip3 install --break-system-packages numpy
# 或更规范：建虚拟环境
python3 -m venv ~/venv && source ~/venv/bin/activate

5.2 想要 GPU 版 PyTorch？官方源不通，走这两条路

  • 路线 A（推荐，最省事）：直接用 ollama。模型库预置、GPU 加速开箱即用、模型从 modelscope 拉。做 Agent Skills 类型的项目完全够。
  • 路线 B：从 ModelScope 找 aarch64 + CUDA 的 torch wheel（modelscope.cn 可达，社区有上传 GB10/aarch64 预编译轮子），或用 pip download 在别处下好再传进来。
  • 路线 C：Docker 走国内镜像加速器（阿里云容器镜像服务等），但 NGC 镜像拉不到，只能用 Docker Hub 的第三方镜像。

5.3 其他注意事项

  • 时区是 UTC，写日志、算时间差、设定时任务时会差 8 小时，记得 export TZ=Asia/Shanghai 或自己换算。
  • 服务必须绑 0.0.0.0（已实测验证），绑 127.0.0.1 公网访问会 502。
  • 8888 / 9000 是真正的公网端口，我已经实测从外网能直接打开。Jupyter、Gradio 一定要加 token/password，用完就关，别挂裸奔的 Web 终端。
  • 磁盘是 1 TB 不是 4 TB，目前用了 101 G、剩 769 G。大模型权重一个就 20~40 G，注意别把盘塞满。
  • 别用 scp 传大文件，50 台机器共用一条公网出口，超 1 GB 请在节点上直接下载。
